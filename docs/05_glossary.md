# Глоссарий

Определения в этом файле используются командой последовательно во всех документах. Если термин определен здесь, в остальных документах используется именно это значение.

## Термины

| Термин | Определение | Источник |
|---|---|---|
| **Обратная связь** | Информация от сотрудников о состоянии команды, процессах и условиях работы, получаемая через опросы, чек-апы и exit-интервью | 01 |
| **Достоверная обратная связь** | Обратная связь, отражающая реальное положение дел и пригодная для принятия решений, ключевая цель проекта | 01, 03 |
| **Вовлеченность** | Показатель вовлеченности сотрудников, измеряемый через регулярные опросы | 01, 02 |
| **Pulse-опрос** | Короткий опрос между основными циклами для отслеживания динамики | 01, 02 |
| **Exit-интервью** | Интервью при увольнении, в котором сотрудник оценивает опыт работы в компании | 01, 02 |
| **Социально желательные ответы** | Ответы, которые сотрудник дает исходя из ожиданий окружения, а не из реального положения дел | 01, 02 |
| **Защитное молчание** | Стратегия, при которой сотрудник не отвечает или дает минимально информативные ответы из-за страха последствий | 01, 02 |
| **Психологическая безопасность** | Условие, при котором сотрудник может говорить правду, не опасаясь репрессий | 01, 03 |
| **Скрытый отток** | Увольнения, причины которых компания не видит из-за искаженной обратной связи | 01, 02 |
| **Проблема (системная проблема)** | Обобщенная формулировка проблемы, одобренная командой и передаваемая наверх, базовый термин TO-BE, заменяет понятие «сигнал» | 03, 04 |
| **Кластер проблем** | Тематическая группа проблем, сформированная внешней ИИ-моделью и подтвержденная HR-аналитиком | 03, 04 |
| **Деанонимизация** | Раскрытие автора ответа через метаданные, малый размер группы, стиль текста или иные косвенные признаки | 01, 02, 03 |
| **Honesty gap** | Разрыв между официальными и неофициальными данными о положении дел в компании | 01 |
| **Performance Review** | Оценка индивидуальной эффективности сотрудника, вне границ данного проекта | 01, 02 |
| **Чек-ап** | Командная встреча по методике Squad Health Check с приватной оценкой 8 параметров и обсуждением разногласий | 03 |
| **Squad Health Check** | Командный инструмент самооценки здоровья команды, адаптированный для HR-контекста | 03 |
| **Приватная оценка** | Индивидуальное заполнение оценок и тегов без привязки к личности, недоступна HR и руководителю | 03, 04 |
| **Детерминированное агрегирование** | Расчет распределений по фиксированным правилам, дает воспроизводимый результат при одинаковых входных данных | 03, 04 |
| **K-анонимность (порог k)** | Правило публикации среза только при достижении минимального размера группы (k ≥ 5) | 03, 04 |
| **Кворум** | Минимальная доля участников, необходимая для признания голосования по проблеме состоявшимся (≥ 70%) | 03, 04 |
| **Поддержка** | Минимальная доля голосов «за» формулировку проблемы (≥ 60%+) | 03, 04 |
| **Фасилитатор** | Нейтральный ведущий командной сессии, не имеет доступа к индивидуальным ответам и не может публиковать проблему вместо команды | 03, 04 |
| **Владелец процесса** | Роль, получающая подтвержденную проблему и обязанность дать видимый ответ в срок | 03, 04 |
| **Специалист по приватности** | Роль, проверяющая проблемы на риск идентификации (H2) и управляющая политикой вызова внешней модели (H6) | 03, 04 |
| **HR-аналитик** | Роль, подтверждающая кластеры и назначающая владельца процесса (H3, H4) | 03, 04 |
| **HR-директор** | Роль, к которой эскалируется просрочка по H4, H6, в основном сценарии не участвует | 03, 04 |
| **Линейный руководитель** | Руководитель команды, в TO-BE не присутствует на командной сессии и не видит индивидуальные ответы | 01, 02, 03 |

## Системы

| Система | Назначение | Используется в |
|---|---|---|
| **Оркестратор циклов** | Создание цикла, параметры, сроки, напоминания, фиксация версии правил приватности | 03 - шаг 1 |
| **Сервис идентификации и токенов** | Проверка права участия, выдача одноразового токена без ФИО | 03 - шаг 2 |
| **Сервис приватного ввода** | Прием оценок и тегов по токену без привязки к личности | 03 - шаг 3 |
| **Детерминированный агрегатор** | Расчет распределений с порогом k ≥ 5 | 03 - шаг 4 |
| **Командная доска** | Отображение агрегатов и расхождений на сессии | 03 - шаг 5 |
| **Сервис командного согласования** | Анонимная фиксация кворума и поддержки формулировки | 03 - шаг 7 (H1), 04 - US-03 |
| **Защита конфиденциальности** | Проверка ПДн, редких ролей, малых групп, уникальных деталей | 03 - шаг 8 (H2), 04 - US-03, US-04 |
| **Сервис обезличивания** | Удаление имен, контактов, названий малых команд перед вызовом ИИ | 03 - шаг 9, 04 - UC-01 (шаг 9) |
| **Реестр системных проблем** | Хранение одобренных формулировок, владельца, срока и статуса | 03 - шаг 9, 04 - US-05 |
| **AI Gateway** | Единственная точка выхода во внешний API, DLP на выходе, zero-retention, журнал вызовов | 03 - шаг 10 (H6), 04 - US-08, UC-03 |
| **Сервис тематической группировки (ИИ)** | Предложение кластера и черновика сводки по очищенному тексту | 03 - шаги 10–11, 04 - US-05 |
| **Рабочее место HR-аналитика** | Подтверждение кластера и назначение владельца | 03 - шаг 11 (H3, H4), 04 - US-05, US-06 |
| **Реестр действий** | Хранение назначенного владельца и срока ответа | 03 - шаг 12 (H4), 04 - US-06 |
| **Публичный трекер действий** | Отображение статуса проблемы для команды без раскрытия данных других команд | 03 - шаг 13 (H5), 04 - US-06, US-07 |
| **Витрина данных** | Агрегаты и статусы для дашбордов внутри контура организации | 03 - шаг 14, 04 - UC-01 (шаг 14) |
| **Журнал решений и аудит** | Запись версий, действий, отмен и эскалаций (WORM), `input_hash` без связи «сотрудник - мнение» | 03 - шаг 14, раздел «Логирование и аудит», 04 - НФТ «Аудит» |
